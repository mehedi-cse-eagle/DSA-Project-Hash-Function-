1. Memory Grid

Words go into numbered boxes. Green = empty, blue = used, red = collision.

Basic concepts (start here)

  • Hash table: a big row of numbered boxes (0, 1, 2, 3...). Think of school lockers: every locker has a number.
  • Hash function: a rule that turns a word into a locker number, so the computer never has to search every locker.
  • ASCII sum: every letter has a secret number (a = 97, t = 116). Add them up. "cat" = 99 + 97 + 116 = 312.
  • Modulo (mod): the remainder after division. 312 mod 7 = 4, because 7 x 44 = 308 and 4 is left. This keeps the number inside the table.
  • Collision: two different words get the same box, for example "cat" and "act". This is normal and must be handled.
  • Linear probing: box taken? Check the next box, then the next, until an empty one is found.
  • Quadratic probing: box taken? Jump 1, then 4, then 9 boxes ahead. This spreads words out better.
  • Chaining: every box keeps a small list, so words that collide simply join the list.
  • Load factor: used boxes divided by total boxes. It shows how full the table is.
  • Rehashing: when the table is 70% full, it grows to the next prime size and every word is placed again, so it stays fast.

How it works, step by step

  1. Type a word and press Insert.
  2. The program adds the ASCII codes of all letters.
  3. It takes the remainder with the table size. That is the box number.
  4. Box empty (green)? The word is stored and the box turns blue.
  5. Box taken? The box flashes red, and the chosen method (linear, quadratic or chaining) finds another place.
  6. Search repeats the same steps, so finding a word is almost instant.
Output appears here.

Collision = two words want the same box. Linear probing tries the next box, quadratic tries +1, +4, +9, chaining links words inside one box. At 70% full the table grows to the next prime size and every word is placed again (rehashing).

2. Password Avalanche

Change one character and the whole hash changes.

Basic concepts (start here)

  • Hash: a long scrambled number made from a password.
  • One-way: easy to make the hash from a password, but practically impossible to get the password back from the hash.
  • Bits: a computer stores numbers as 0s and 1s. This hash has 64 of them.
  • XOR and bit shifting: small mixing tricks that stir the 0s and 1s together.
  • Avalanche effect: change just one letter and about half of all bits change. The result looks totally different.
  • Why it matters: a website saves only the hash. Even if its database leaks, hackers see scrambled numbers, not passwords. (This is a demo; real systems use stronger methods like bcrypt.)

How it works, step by step

  1. Type two passwords that differ by one character.
  2. Each letter is mixed into a running number using XOR, multiply and shift.
  3. Two 64-bit hashes appear.
  4. Bits that differ are shown in red, with the count.

Red bits differ. A tiny change flips about half of the 64 bits, so hashes cannot be guessed. (Demo only, not real security.)

3. Plagiarism Scanner

Finds copied pieces by comparing hashes of small text windows.

Basic concepts (start here)

  • Plagiarism: copying someone else’s text.
  • Window: a small piece of text with fixed length, for example 5 letters.
  • Sliding window: the window moves one letter at a time across the whole text.
  • Hash of a window: each window becomes one number, and comparing two numbers is faster than comparing letters.
  • Rolling hash: to move the window, remove the first letter’s part and add the new letter. No need to start again, so it is O(1).
  • Rabin-Karp: the algorithm that uses this idea to find matching pieces quickly.
  • Double check: if hashes match, the letters are compared too, to avoid a false alarm.
  • Similarity %: copied letters divided by total letters.

How it works, step by step

  1. Paste the original text and the suspect text.
  2. Every window of both texts is turned into a hash.
  3. Equal hashes are checked letter by letter.
  4. Matching parts turn yellow, and the percentage is shown.

The window slides one letter at a time. The rolling hash drops the first letter and adds the next, so each step costs O(1).

4. LRU Cache

Only 3 fast slots. When full, the oldest unused item is evicted.

Basic concepts (start here)

  • Cache: a small, very fast memory that keeps recently used things, like web pages in a browser.
  • Why small: fast memory is expensive, so it can only hold a few items. Here it holds 3.
  • Hit: the item is already in the cache. Very fast.
  • Miss: the item is not in the cache, so it must be loaded.
  • LRU (Least Recently Used): when the cache is full, remove the item that was not used for the longest time.
  • Eviction: the removal of that oldest item.
  • Hash map + linked list: the map finds any item instantly, the list keeps the order from newest to oldest. Together every step is O(1).

How it works, step by step

  1. Type a page name and press Request.
  2. Already there (hit)? It moves to the newest position.
  3. Not there (miss) and a slot is free? It is added.
  4. Not there and all 3 slots are full? The oldest turns red and is evicted, then the new one is added.
Newest on the left, oldest on the right.

Asking for something already cached is a hit and moves it to the newest spot.

5. Break the Hash

Pick a target box. Find a word that lands exactly there. 3 attempts.

Basic concepts (start here)

  • Target box: the box number you must hit, chosen by you.
  • Goal: find any word whose ASCII sum mod table size equals the target.
  • Pigeonhole idea: there are endless words but only a few boxes, so many different words must share a box.
  • What you learn: collisions are unavoidable, which is why every hash table needs a collision method.

How it works, step by step

  1. Choose a table size and a target box, then press Start.
  2. Type a word. The program shows its ASCII sum and the remainder.
  3. Remainder equals target? You broke the hash and win.
  4. You have 3 attempts.
Press Start.

Hint: change letters until the ASCII sum has the right remainder.
